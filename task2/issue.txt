## 과제 목표
이번 과제를 통해 Vanilla JS로 구현한 Todo 앱을 React Function Component로 리팩토링하며 다음을 배우고자 했어요.

- React의 useState/useEffect를 이용한 상태 관리와 사이드 이펙트 처리
- 컴포넌트 기반 아키텍처로 UI를 분리하고 props로 데이터 전달하는 방식 이해
- Vanilla JS의 DOM 조작에서 React의 선언적 렌더링으로의 패러다임 변화 경험
- AI를 활용해 마이그레이션하고 생성된 코드를 직접 읽고 수정하는 디버깅 흐름 익히기

## AI 활용 내역

### 전체 컴포넌트 구조 설계
- **AI 활용**: 1차 과제 (Vanilla JS) 코드를 제공하고, React Function Component로 마이그레이션할 전체 구조를 요청했어요.
- **생성 결과**: App.jsx (상태 관리), 7개의 특화된 컴포넌트 (TodoForm, TodoList, TodoItem, FilterTabs, DailyHeader, WeeklyCalendar, EmptyState)
- **직접 수정한 부분**:
  - 컴포넌트 간 props 흐름을 명확하게 정리하고, 불필요한 상태 끌어올리기 최소화
  - localStorage 초기화 시 함수형 초기화 패턴 적용 (성능 개선)
  - console.error 제거하여 프로덕션 준비
- **수정 이유**: 더 깔끔한 데이터 플로우와 최적화된 성능이 필요했어요.

### Todo 인라인 수정 기능
- **AI 활용**: prompt() 대신 input 필드로 수정하는 방식을 구현해달라고 요청
- **생성 결과**: TodoItem 컴포넌트에서 `isEditing` 상태로 UI를 전환하는 코드
- **직접 수정한 부분**:
  - useRef를 사용해 수정 시 input에 자동 포커스 + 커서를 끝으로 이동
  - 엔터키(Enter), 이스케이프(Escape) 키 처리 추가
  - 로컬 에러 상태로 유효성 검증 표시
- **수정 이유**: UX를 개선하고 키보드 네비게이션을 지원하기 위함

### 주간 뷰 달력 구현
- **AI 활용**: 주의 시작일부터 7개 날짜를 표시하고, 선택된 날짜와 오늘 날짜를 구분하는 로직을 요청
- **생성 결과**: WeeklyCalendar 컴포넌트에서 각 날짜별 Task 개수 표시

  - 주간 범위를 벗어나면 선택 날짜 업데이트
- **수정 이유**: 달력 UI의 시각적 명확성을 위함

## 구현하면서 고민한 점

### 상태 관리 계층화
- **고민한 점**: 여러 자식 컴포넌트가 필요로 하는 상태를 어디까지 App.jsx에 두고, 어디부터 지역 상태로 관리할지 결정하는 것이 어려웠어요.
- **해결 방법**:
  - 전역이 필요한 상태 (todos, selectedDate, selectedFilter, editingTodoId): App.jsx
  - 지역만 필요한 상태 (TodoForm의 입력값, TodoItem의 수정 텍스트): 각 컴포넌트
  - 이렇게 명확히 분리하니 props 체이닝이 줄어들었어요.

### localStorage와 useEffect의 의존성 배열
- **고민한 점**: todos가 바뀔 때마다 localStorage에 저장되어야 하는데, useEffect의 의존성 배열을 어떻게 관리해야 할지 고민했어요.
- **해결 방법**:
  - todos를 의존성 배열에 포함: `useEffect(() => { localStorage.setItem(..., JSON.stringify(todos)) }, [todos])`
  - 이렇게 하면 todos가 변할 때만 저장되고, 무한 루프도 없어요.

### React와 Vanilla JS의 차이 체감
- **고민한 점**: Vanilla JS에서 직접 DOM을 조작했던 방식 (e.g., querySelector, textContent 변경)이 React에서는 어떻게 표현되는지 이해하기.
- **해결 방법**:
  - Vanilla: `document.querySelector('#todo-list').innerHTML = ...`
  - React: `todos.map(todo => <TodoItem key={todo.id} />)`
  - 이렇게 비교하니 선언적 렌더링의 장점이 명확하게 느껴졌어요.

## 과제 회고

### 잘한 점
- 컴포넌트를 적절한 크기로 분리해 재사용성과 가독성을 높였어요. (7개의 특화된 컴포넌트)
- localStorage와 localStorage 초기화 시 함수형 초기화 패턴을 적용해 성능을 고려했어요.
- 다크 모드, 빈 상태 처리, 입력값 검증 등 세부적인 UX를 신경썼어요.
- AI가 생성한 코드를 단순히 받아들이지 않고, 직접 읽고 수정하며 이해하려고 노력했어요.

### 아쉬운 점
- 초기 컴포넌트 설계 때 AI에 의존하면서 전체 구조를 깊이 있게 이해하는 데 시간이 걸렸어요.
- 주간 뷰의 날짜 계산 로직이 조금 복잡한데, 더 간단하게 리팩토링할 수 있을 것 같아요.
- 스타일링은 Tailwind이 자동으로 해주다 보니 CSS를 더 깊이 있게 배우지 못한 아쉬움이 있어요.
